# AliCCP 参数高效集成：筛查实验预注册

## 决策与边界

本方向只检验「共享一个冻结 Stage-1 backbone 和一个 Stage-2 NewTask 主头，两个小型残差预测头能否提供有用的预测多样性」。这是工程消融，不主张集成或低秩适配器本身具有方法新颖性。两个备选是完整双 NewTask 集成（参数和训练成本近乎翻倍）及单头加宽（无法检验集成多样性）；首轮选共享主头 + 两个 rank-8 残差头，并加入参数量匹配的单 rank-16 残差头对照。

分支 `exp/aliccp-parameter-efficient-ensemble` 只从纯公平基线 `8133d32` 派生；不继承 Residual Prompt，不修改 `multitaskrec/*`、`config.py`、原始 AliCCP 数据或公平基线协议。先提交本预注册，再写测试和代码，再运行 smoke，最后正式短实验。不得合并 master。

## 公平配对

- 数据：AliCCP `p2M-v500k-t1M` 前缀，BSI 为新任务；canonical model seed `1688723512`。训练、验证、测试前缀和指纹必须一致。
- 所有臂使用同一个已冻结 Stage-1 checkpoint（相同 `stage1_id` 与 backbone SHA），Stage-2 从头初始化。正式实验三臂：B = 原始 NewTask；C = 同一 NewTask + 一个 rank-16 残差头；E = 同一 NewTask + 两个 rank-8 残差头，其概率均值为集成输出。不得用不同 Stage-1 或旧分支结果充当配对对照。
- 残差头输入仅为 NewTask 已形成的 fused representation，不读取官方 val/test 标签；以近零初始残差作用于概率 logit。C 与 E 的可训练参数量应相差不超过 5%，且 E 的总可训练参数少于两个完整 NewTask 的总数。若无法满足，正式运行前 NO-GO。
- B/C/E 均按相同数据顺序、batch=2000、Adam lr=1e-4、最多 5 epoch、patience=2 训练。以各臂自身 val BSI AUC 选 checkpoint；test 只评一次。每臂训练数据暴露量相同，记录 wall time、参数数目和计算量差异，不宣称等算力。
- E 的两个头对每个样本分别计算 BCE 后取平均训练；共用主头但各自独立初始化。C 的单头采用相同训练目标。集成只在推理时对两个概率求算术平均。不要用 test 挑权重、阈值或融合规则。

## 机制门禁与结果规则

在正式实验前，单元测试须证明：两个残差头参数不共享、各自有非零梯度、零残差时输出与主头相同、对照与集成参数预算匹配、集成均值计算正确、冻结 backbone 的参数/梯度/SHA 不变。Smoke 只检验可运行性，不用于选方案。

正式结果从 raw 预测、标签、配置与 checkpoint 由独立解析器重算，核验样本数、seed、前缀指纹、Stage-1 SHA、代码 commit、`git.dirty=false`、预算、val 选点和运行时间。记录三臂 val/test AUC、E−B、E−C、C−B 的配对差值、E 两头的平均绝对预测差、相关系数和预测分歧分布、参数量比与时间比。若 E 两头预测完全相同或训练后平均绝对差低于 1e-4，判机制塌缩，不把正向 AUC 归因于集成。

旧预注册结论不覆盖；新分类仅追加：同配置配对 test AUC 差值 >= +0.001 为「正提升」，-0.02 < 差值 < +0.001 为「无明显提升」，<= -0.02 为「明显衰退」。只有 E−C 与 E−B 均达到 +0.001、val 方向一致、机制未塌缩且所有真实性门禁通过，才允许另建独立种子扩展分支；否则记录并关闭本变体。无明显提升还需结合机制、val 方向及成本判断是否有提升空间，不能自动调参。

结果不好但协议有效必须保存；确认错误的派生汇总作废并删除，从 raw 或正确重跑重建。原始有效数据、配置、日志、机制统计与判定均提交并推送。
